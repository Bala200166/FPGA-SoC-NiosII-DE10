# Lab 2 - Avalon Bus and SignalTap Analysis

## Overview

FPGA/SoC laboratory using the **Nios II soft-core processor** and the **Avalon memory-mapped bus** on a DE10 FPGA platform.

The work focused on memory-mapped communication between software and FPGA peripherals, together with internal bus debugging using **Intel SignalTap Logic Analyzer**.

> **Team coursework:** Completed as part of a three-member student team. The original report contains the names of all contributors.

## Work Completed

- Configured a Nios II-based SoC using **Intel Platform Designer/Qsys**.
- Worked with on-chip memory, JTAG UART and a custom memory-mapped IP.
- Accessed FPGA hardware from C using memory-mapped addresses.
- Performed read and write operations at specific address offsets.
- Wrote sequences of values to successive memory locations.
- Observed Avalon bus activity generated by software accesses.
- Configured SignalTap to capture internal FPGA signals.
- Analyzed address, write-data and control signals.
- Related Nios II C operations to the corresponding Avalon bus transactions.
- Examined timing between successive memory-write operations.

## Key Implementation

The custom hardware block was accessed from C through its base address.

Example:

```c
pTable = (int *)TST_IP_BASE;
*(pTable + 56) = 0xAA55AA55;
```

Memory-mapped accesses from the Nios II processor generated corresponding transactions on the Avalon interconnect.

SignalTap was used to observe internal signals associated with these transactions, including:

- address
- write data
- read/write control
- peripheral selection
- transaction timing
